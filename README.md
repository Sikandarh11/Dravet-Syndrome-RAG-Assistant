# Dravet Syndrome RAG Assistant

An AI question-answering project for Dravet Syndrome built around retrieval-augmented generation (RAG). The app searches a local document index, assembles the most relevant context, and generates a concise answer using either a local Ollama model or Groq when online.

## What This Project Does

- Loads PDFs from the `data/` folder.
- Splits them into chunks and stores them in a FAISS vector index.
- Uses embeddings to retrieve the most relevant passages for a user question.
- Generates an answer with either:
  - `TinyLlama` through Ollama for offline/local use, or
  - `Groq` for online generation when a valid API key is available.

## Requirements

- Windows, macOS, or Linux
- Python 3.10+ recommended
- Ollama installed locally
- Python virtual environment recommended (`myvenv` in this project)
- Optional: Groq API key for online generation

## Environment Variables

Create a `.env` file in the project root if you want to use Groq:

```env
GROQ_API_KEY=your_groq_api_key_here
```

If `GROQ_API_KEY` is not set, the app falls back to local Ollama generation when available.

## Install Ollama

Ollama is required for this project because embeddings are loaded locally from `localhost:11434`.

On Windows, run PowerShell as Administrator:

```powershell
winget install Ollama.Ollama
```

Then start the Ollama service:

```powershell
ollama serve
```

Pull the models used by this project:

```powershell
ollama pull nomic-embed-text
ollama pull tinyllama
```

Verify the models:

```powershell
ollama list
```

## Prepare the Knowledge Base

Put your PDF files into the `data/` folder, then build the vectorstore:

```powershell
python populate_database.py
```

To rebuild everything from scratch:

```powershell
python populate_database.py --reset
```

## Ask Questions

Run the query script with a question:

```powershell
python query_data.py "What are common seizure triggers in Dravet syndrome?" --k 3
```

Useful flags:

- `--k 3` controls how many chunks are retrieved.
- `--no-stream` disables token streaming for local generation.
- `--force-offline` skips the internet check and uses Ollama directly.

Examples:

```powershell
python query_data.py "What medicines are commonly used for Dravet syndrome?" --k 3
python query_data.py "What are common seizure triggers?" --force-offline
python query_data.py "Explain SCN1A mutations in Dravet syndrome" --no-stream
```

## How It Works

1. The query is embedded using `nomic-embed-text` through Ollama.
2. FAISS searches the local vectorstore for the closest chunks.
3. The script trims context to keep prompts small.
4. The answer is generated by either Groq or local TinyLlama.

## Helper Scripts

- `populate_database.py`: Builds or updates the FAISS index from PDFs.
- `check_db.py`: Prints stored documents and metadata for inspection.
- `test_script.py`: Checks that dependencies, Ollama, and local models are installed.
- `test_rag.py`: Runs a basic evaluation-style query against the pipeline.

## Troubleshooting

### `query_text` argument is missing

You must pass a question to `query_data.py`:

```powershell
python query_data.py "Your question here"
```

### Ollama connection error

If you see an error connecting to `http://localhost:11434`, start Ollama first:

```powershell
ollama serve
```

Then verify the models are installed:

```powershell
ollama list
```

### Vectorstore is empty or missing

Make sure PDFs are inside `data/` and then rebuild the index:

```powershell
python populate_database.py --reset
```

### Groq is not being used

Check that `GROQ_API_KEY` is set in `.env`. If not, the script falls back to Ollama.

## Notes

- Keep `.env` out of version control.
- This project is optimized for local/offline use, so Ollama is the default runtime dependency.
- For slow internet, the safest workflow is to use local Ollama generation with `--force-offline`.
